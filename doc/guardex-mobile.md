# Мобильный Guardex

Production не обновляется автоматически: изменения подготовлены для проверки в feature/dealer-handbook. Пользователь приостановил выкладку.

## Поведение

- На экранах до 760 px чат — отдельная поверхность размером с видимую область. Документ не прокручивается; переписка и история имеют независимую прокрутку.
- VisualViewport resize/scroll обрабатываются через requestAnimationFrame. Учитываются высота, offsetTop, изменение ориентации и Android-режим с изменением layout viewport. Небольшие колебания не записываются повторно. Pinch zoom не принимается за клавиатуру.
- При экранной клавиатуре нижние вкладки скрыты, поле ввода находится над клавиатурой. При blur панель не появляется до восстановления высоты viewport. Safe-area учтена отдельно.
- Размер шрифта всех текстовых полей в мобильном чате не меньше 16 px. Масштабирование пользователем не запрещается. Отправка касанием сохраняет фокус composer, ввод не закрывается специально после отправки. Поле растёт до 144 px и затем прокручивается внутри.
- Существующие сообщения сохраняют DOM-узлы при появлении новых ответов; весь лог не пересоздаётся. Изменение размера изображений и поля ввода учитывается ResizeObserver.
- Автопрокрутка работает при чтении последних сообщений. Если пользователь ушёл вверх, ответ не возвращает его вниз. Кнопка перехода к последнему сообщению включает следование. При переключении чатов сохраняется позиция чтения в текущей сессии.
- Дополнительные ссылки документов перенесены в боковую панель. Мобильный composer компактный, сообщения не анимируются при каждом обновлении. Контролы имеют увеличенные области нажатия. Открытая мобильная история делает основную поверхность inert, аппаратный Tab остаётся внутри истории.

## Проверки

`npm test` включает модель VisualViewport: Safari-подобный offset, закрытие клавиатуры, Android resize-content, pinch и ориентация. `npm run test:mobile` проверяет длинную историю, стабильность DOM, остановку автопрокрутки, сохранение фокуса, синтетический viewport клавиатуры, границы composer, возврат нижней панели и позиции истории. Используются Chromium с мобильной эмуляцией и локальные тестовые ответы API, а не production.

Настоящая клавиатура iOS, интерактивное закрытие клавиатуры свайпом, системные панели Safari и standalone-режим требуют финального прогона на устройстве. Chromium-эмуляция этого не подтверждает. Шрифты тестового окружения ранее имели ограничение отрисовки; проверять реальные текстовые переносы на iPhone дополнительно.

API: https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport
