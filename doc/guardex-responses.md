# Ответы Guardex

Guardex отображает текст как Markdown (GFM): заголовки, таблицы, вложенные списки, цитаты, ссылки, зачёркивание, задачи и блоки кода с копированием. Парсер `marked` и очистка `DOMPurify` поставляются локально, без CDN. Исходный HTML из Markdown отображается текстом. Изображения из произвольного Markdown не загружаются; изображения товаров берутся из каталога.

`PSLChatFormat.render(text)` — общий рендерер Markdown. `PSLChatBlocks.render(blocks)` — единый набор визуальных компонентов. Изменение шаблона применяется к новым и уже сохранённым сообщениям. Из модели или API передаются данные, а не HTML/JavaScript.

## Контракт сообщения

```json
{
  "role": "assistant",
  "text": "## Материалы для проекта\nОписание и **важные свойства**.",
  "blocks": [
    {"type": "products", "ids": ["wiron"]},
    {"type": "callout", "title": "Обратите внимание", "text": "Условия применения сверяйте с техкартой."},
    {"type": "markdown", "text": "### Дополнительная информация\nЛюбой поддерживаемый Markdown."},
    {"type": "table", "columns": ["Параметр", "Значение"], "rows": [["Источник", "Каталог PSL"]]},
    {"type": "details", "title": "Подробнее", "text": "Дополнительный Markdown."},
    {"type": "links", "items": [{"title": "Каталог PSL", "description": "Все материалы", "url": "/"}]}
  ]
}
```

Также поддерживаются `comparison` (два ID товара) и `floor` (до трёх ID). Порядок блоков сохраняется; через `markdown` можно вставлять текст между карточками, таблицами и схемами. Цены, изображения и названия карточек берутся из текущего каталога. Неизвестные товары не создаются. Неизвестный тип блока отображает его `text`/`content` как Markdown.

Для нового компонента приложение регистрирует доверенный рендерер до обработки сообщений:

```js
PSLChatBlocks.register('project-note', block =>
  '<section class="answer-callout">' + PSLChatFormat.render(block.text) + '</section>'
);
```

Результат рендера очищается DOMPurify. Регистрировать функции из текста ответа или выполнять переданный JavaScript нельзя. Для обычного нового содержимого достаточно Markdown, отдельный компонент не требуется.

Пока используется локальный подбор по каталогу. Подключение ответов Operator/обученного ИИ — отдельный этап; этот контракт подготовлен для его ответов.

Проверки: `npm ci && npm test`. Проверки рендера используют JSDOM. Для E2E: `npx playwright install chromium --only-shell && npm run test:ui`. Интерфейс проверяется на ширинах 1440, 390 и 337 px с тестовым API. Можно передать путь к имеющемуся Chromium через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.
